# 吃点啥 - 校园餐饮与商户评价推荐平台 项目需求文档

## 一、项目概述

### 1.1 项目背景

"吃点啥"是一个面向校园的餐饮与商户评价推荐平台，旨在帮助学生快速选择就餐地点和菜品，同时为商家提供数据支持和用户反馈渠道。

### 1.2 平台覆盖范围

平台覆盖多种餐饮场景：
- **食堂**：校园内各食堂，包含多个独立窗口
- **校内店铺**：不属于食堂但在校园内的独立店铺
- **校园周边店铺**：不在校园内的独立合作商户

### 1.3 用户角色

| 角色 | 说明 |
|------|------|
| 学生用户 | 平台的主要使用者，可浏览菜品、发表评价、参与抽奖等 |
| 卖家/商家 | 食堂窗口或店铺经营者，可管理菜品、查看反馈、发布推荐 |
| 管理员 | 平台管理人员，负责审核商家入驻、管理内容、查看统计数据 |

## 二、功能模块

### 2.1 认证模块

#### 2.1.1 学生微信登录
- 学生用户通过微信小程序授权登录
- 登录成功后获取 JWT Token 和刷新令牌
- 支持判断是否为新用户

#### 2.1.2 卖家微信登录
- 卖家通过微信小程序授权登录
- 返回商家ID、入驻申请状态和商家营业状态

#### 2.1.3 Android账号登录
- Android端普通账号通过账号密码登录
- 返回用户角色信息用于判断权限

#### 2.1.4 Android账号注册
- Android端注册普通账号
- 用户名4-64位，全局唯一；密码6-64位
- 注册成功后默认绑定 STUDENT 角色

#### 2.1.5 管理员登录
- 平台管理员通过账号密码登录

#### 2.1.6 Token管理
- 支持使用刷新令牌获取新的Token对
- 支持用户登出，使Token失效

#### 2.1.7 修改密码
- 登录用户可修改密码，新密码6-64位

---

### 2.2 用户模块

#### 2.2.1 个人信息管理
- 学生用户可查看个人信息（昵称、头像、手机号等）
- 支持更新个人信息

#### 2.2.2 偏好设置
- 用户可设置默认就餐商业区
- 可设置价格范围偏好（最低/最高价格）

- 可设置忌口标签（如香菜、芹菜等）

### 2.4 商家模块

#### 2.4.1 商家列表

### 2.19 小法庭模块

#### 2.19.1 发起庭审
- 学生和商家均可发起庭审
- 发起庭审需关联相关订单、菜品或评价
- 需填写纠纷类型和详细描述
- 支持上传举证图片（最多9张）

#### 2.19.2 纠纷类型
- 菜品质量：如变质、异物、与描述严重不符
- 分量问题：分量明显不足
- 价格纠纷：乱收费、价格欺诈
- 服务态度：商家态度恶劣、辱骂等
- 卫生问题：环境脏乱、食品安全问题
- 其他纠纷：其他未分类的争议

#### 2.19.3 庭审流程
- 发起庭审后进入举证阶段（双方可补充证据）
- 举证阶段结束后进入投票阶段
- 投票结束后系统自动统计结果

#### 2.19.4 用户投票
- 登录用户可参与庭审投票
- 每个用户对同一案件只能投票一次
- 投票时可选择支持买家或卖家
- 投票时可选择匿名或公开

#### 2.19.5 庭审结果
- 根据投票结果自动判定胜负
- 结果类型：买家胜、卖家胜、平局
- 记录双方得票数和投票比例

#### 2.19.6 庭审记录
- 用户可查看自己发起或参与的庭审
- 支持按状态筛选：进行中、已结束
- 显示庭审详情、双方陈述、投票结果

#### 2.19.7 庭审大厅
- 展示正在进行中的庭审案件
- 用户可浏览并参与投票
- 支持分页查询

## 三、系统约束

### 3.1 技术规范
- RESTful API 设计
- Base URL: `/api/v1`
- 认证方式：JWT Token
- 数据格式：JSON
- URL路径全小写，中划线分隔

### 3.2 通用响应格式
- 成功响应：`{ "code": 200, "message": "success", "data": {...} }`
- 分页响应：包含 records、total、page、size 字段
- 错误响应：`{ "code": 4xx/5xx, "message": "错误描述", "data": null }`

### 3.3 分页规范
- 默认页码：1
- 默认每页数量：10
- 最大每页数量：50

## 四、状态枚举

### 4.1 用户状态
- `ACTIVE`：正常
- `DISABLED`：已禁用

### 4.2 商业区类型
- `CANTEEN`：食堂
- `CAMPUS_SHOP`：校内店铺
- `PERIPHERY_SHOP`：校园周边店铺

### 4.3 商家申请状态
- `PENDING`：待审核
- `APPROVED`：已通过
- `REJECTED`：已驳回

### 4.4 商家状态
- `OPEN`：营业中
- `CLOSED`：已关闭
- `PENDING`：待审核

### 4.5 菜品状态
- `ON_SALE`：上架中
- `SOLD_OUT`：已售罄
- `OFF_SHELF`：已下架
- `PENDING`：待审核

### 4.6 推荐类型
- `TODAY`：今日主推
- `NEW`：新品
- `SPECIAL`：特色
- `VALUE`：高性价比
- `SIGNATURE`：招牌

### 4.7 反馈类型
- `TASTE`：口味
- `PORTION`：分量
- `PRICE`：价格
- `SERVICE`：服务
- `HYGIENE`：卫生
- `OTHER`：其他

### 4.8 反馈状态
- `PENDING`：待查看
- `VIEWED`：已查看
- `ACCEPTED`：已采纳
- `IMPROVED`：已改进
- `REJECTED`：暂不处理

### 4.9 抽奖结果行为
- `NONE`：无操作
- `ACCEPT`：接受
- `SKIP`：跳过
- `FAVORITE`：收藏

### 4.10 抽奖模式
- `RANDOM`：随机抽奖
- `CONDITION`：条件抽奖
- `FAVORITE`：从收藏中抽

### 4.11 收藏类型
- `DISH`：商家菜品
- `POST`：学生分享

### 4.12 帖子状态
- `PUBLISHED`：已发布
- `DELETED`：已删除

### 4.13 改进记录状态
- `DRAFT`：草稿
- `PUBLISHED`：已发布
- `ARCHIVED`：已归档

### 4.14 想吃清单状态
- `WANT_TO_EAT`：想吃
- `EATEN`：已吃
- `CANCELLED`：已取消

### 4.15 庭审状态
- `EVIDENCE`：举证阶段
- `VOTING`：投票阶段
- `CLOSED`：已结束

### 4.16 纠纷类型
- `QUALITY`：菜品质量
- `PORTION`：分量问题
- `PRICE`：价格纠纷
- `SERVICE`：服务态度
- `HYGIENE`：卫生问题
- `OTHER`：其他纠纷

### 4.17 庭审结果
- `BUYER_WIN`：买家胜
- `SELLER_WIN`：卖家胜
- `DRAW`：平局
