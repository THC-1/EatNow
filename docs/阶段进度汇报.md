## 一、项目概述

"饭点盲盒"是一个校园食堂菜品评价与推荐平台，面向**学生**（微信小程序）、**商家**（微信小程序）、**平台管理员**（Web后台）三类用户。核心场景是解决学生"今天吃什么"的选择困难问题，通过趣味化抽奖推荐和评价反馈闭环，帮助学生提升就餐体验，帮助食堂商家优化服务质量。

**技术栈**：
- 后端：Java 17 + Spring Boot 3.5 + Spring Security 6 + MyBatis-Plus + MySQL + JWT
- 前端（小程序）：uni-app + Vue.js，编译目标为微信小程序
- 前端（管理后台）：Vue.js Web 端
- 开发工具：IntelliJ IDEA、HBuilderX、Navicat、Git

## 三、超前完成的额外功能

以下功能**不在原定三阶段计划中**，但已开发完成：

### 3.1 学生美食分享社区（Student Post）

这是一个完整的社交模块，让学生分享自己的美食发现：

- **发布帖子**：标题、美食名称、店铺名称（带实时地点搜索自动补全）、价格、评分、正文内容（500字）、图片上传（最多6张）、分类、口味标签
- **帖子浏览**：关键字搜索、按食堂/分类/标签筛选、按最新/最热排序、下拉刷新、无限滚动分页
- **帖子互动**：点赞/取消点赞、收藏/取消收藏、查看浏览量
- **帖子管理**：查看我的帖子、删除自己的帖子
- **参与抽奖**：发布时可选择"加入抽奖池"，帖子也会被纳入抽奖系统

**数据表**：student_post、student_post_image、student_post_tag、student_post_like 共4张表

### 3.2 想吃清单（Eat List / Meal Planning）

超越简单收藏的餐食规划功能：

- 将菜品加入"想吃"清单
- 标记为"已吃"（支持添加用餐笔记和时间）
- 取消想吃
- 与抽奖结果关联（从抽奖加入的菜品自动记录来源）
- 状态生命周期：想吃 → 已吃/取消

**数据表**：eat_list

### 3.3 用户偏好系统

学生可设置个人偏好，用于条件抽奖筛选：

- 默认食堂
- 预算范围（最低/最高价格）
- 口味偏好
- 忌口标签

**数据表**：user_preference

### 3.4 多态收藏系统

收藏功能支持多种目标类型，而非仅限菜品：

- 收藏菜品（DISH）
- 收藏帖子（POST）
- 统一的收藏检查和计数维护接口

**数据表**：favorite（多态设计，targetType + targetId）

### 3.5 多维评分体系

评价系统设计了四维评分而非单一分数：

- 综合评分（overall）
- 口味评分（taste）
- 分量评分（portion）
- 性价比评分（value）

评价创建/删除后，系统自动重新计算菜品和商家的聚合评分。

### 3.6 Android 端登录支持

除微信小程序登录外，还实现了用户名密码登录/注册，为未来Android端预留：

- `POST /api/v1/auth/android/login`
- `POST /api/v1/auth/android/register`

### 3.7 商家入驻的两种路径

- **食堂窗口模式**：选择食堂 → 选择窗口 → 提交申请
- **独立店铺模式**：选择校园店铺或周边商铺 → 自动创建门店 → 提交申请

### 3.8 统一文件上传服务

集中化的图片上传接口，支持5种业务类型：

- 头像（avatar）
- 菜品图片（dish）
- 评价图片（review）
- 帖子图片（post）
- 商家Logo（merchat-logo）

按类型自动分目录存储，UUID防冲突。

## 五、核心业务闭环实现情况

原设计的核心闭环已全部实现：

```
卖家发布菜品
       ↓
学生浏览菜品（食堂/窗口/菜品列表 → 详情页）
       ↓
学生通过抽奖/排行榜/分享社区选择菜品
       ↓
学生收藏/加入想吃清单
       ↓
学生就餐后评价（四维评分+文字+图片）/ 留言反馈
       ↓
卖家查看反馈并回复 → 发布改进记录
       ↓
平台管理员审核卖家、管理菜品、审核评论、查看统计数据
       ↓
平台根据评分、收藏、反馈持续优化推荐
```

## 六、安全架构

- **认证方案**：Spring Security 6 + JWT 无状态认证
- **Token设计**：双Token模式（短期Access Token + 长期Refresh Token），支持自动续期
- **Token黑名单**：登出时将Token加入内存黑名单，防止重放攻击
- **密码加密**：BCrypt
- **权限控制**：三角色（STUDENT/MERCHANT/ADMIN）+ 方法级安全检查
- **公开接口**：登录端点和所有只读GET查询（食堂、菜品、评价、排行榜等）
- **错误处理**：自定义401/403 JSON响应，全局异常处理
