# 吃点啥 - 校园食堂菜品评价与推荐平台

## 一、项目背景

在校园生活中，学生每天都面临"今天吃什么"的问题。食堂菜品种类多，但信息分散，学生往往只能依靠个人经验、同学推荐或临时选择，容易出现选择困难、踩雷、排队后发现不合口味等情况。

同时，食堂商家也缺少一个直接了解学生评价和需求的平台。学生对菜品口味、分量、价格、服务等方面的反馈通常散落在聊天群或线下交流中，商家难以及时收集和改进。

因此，本项目设计"饭点盲盒"校园食堂菜品评价与推荐平台，通过微信小程序连接学生和商家，为学生提供菜品浏览、评分评价、收藏、排行榜和抽奖推荐功能，也为商家提供菜品推荐、留言查看和反馈改进功能。平台管理员则通过 Web 后台进行用户、商家、菜品和内容的统一管理。

## 二、用户角色设计

本项目设计三个角色：

| 角色        | 端类型      | 说明      | 平台  |
| --------- | -------- | ------- | :-- |
| 学生用户      | 微信小程序    | 平台主要使用者 | 小程序 |
| 卖家 / 食堂商家 | 微信小程序    | 菜品提供者   | 小程序 |
| 平台管理员     | Web 管理后台 | 平台治理者   | web |

这样设计很合理，因为学生和卖家的使用场景都偏移动端，而平台管理员需要处理审核、统计、权限等复杂操作，更适合电脑端 Web 后台。

## 三、角色一：学生用户

学生用户是平台的主要使用者，核心目标是：

- 快速找到想吃的菜
- 避免踩雷
- 记录喜欢的菜
- 通过评价表达真实感受

### 3.1 登录与个人信息

学生通过微信授权登录进入小程序。首次登录时，系统自动创建学生账号。学生可以完善个人资料，例如：

- 昵称
- 头像
- 常去食堂
- 口味偏好
- 预算范围
- 忌口信息

其中，常去食堂、口味偏好和预算范围可以用于后续抽奖推荐。

### 3.2 菜品浏览

学生可以查看校园内不同食堂、窗口和商家的菜品信息。

主要功能包括：

- 查看食堂列表
- 查看商家 / 窗口列表
- 查看菜品列表
- 查看菜品详情
- 按食堂筛选
- 按价格筛选
- 按口味筛选
- 按评分筛选
- 搜索菜品

菜品详情页可以展示：

- 菜品图片
- 菜品名称
- 所属食堂
- 所属商家 / 窗口
- 价格
- 评分
- 口味标签
- 推荐理由
- 用户评论
- 收藏人数

### 3.3 "今天吃什么"抽奖功能

这是项目的核心特色功能。学生可以通过抽奖形式决定吃什么，降低选择困难。

抽奖方式包括：

- 全平台随机抽
- 按食堂范围抽
- 按价格范围抽
- 按口味标签抽
- 按评分范围抽
- 从收藏菜品中抽
- 从想吃清单中抽

抽奖结果展示：

- 今日推荐菜品
- 所属食堂 / 商家
- 价格
- 评分
- 标签
- 推荐理由
- 查看详情
- 再抽一次
- 加入收藏
- 我就吃它

这个功能是项目最有记忆点的地方，建议作为首页核心入口。

### 3.4 收藏与想吃清单

学生可以把感兴趣的菜品加入个人清单。

功能包括：

- 收藏菜品
- 取消收藏
- 加入想吃清单
- 标记已吃过
- 查看我的收藏
- 查看我的想吃清单
- 查看抽奖历史

这样可以让用户行为形成闭环：

```
浏览菜品 → 收藏 / 想吃 → 抽奖推荐 → 实际就餐 → 评价反馈
```

### 3.5 评价与留言

学生吃过菜品后，可以对菜品进行评价。

评价内容包括：

- 综合评分
- 口味评分
- 分量评分
- 性价比评分
- 文字评价
- 图片评价（可选）
- 是否匿名（可选）

留言内容可以分成两类：

- **菜品评价**：公开展示给其他学生看
- **商家留言**：给商家作为改进建议

例如：

> "这个鸡腿饭味道不错，但最近分量有点少。"
> "希望麻辣烫窗口可以增加不辣汤底。"
> "这个套餐性价比高，适合午饭。"

学生也可以对评论进行点赞，帮助优质评论获得更高曝光。

### 3.6 排行榜

学生可以查看不同类型的榜单。

建议包括：

- 好评榜
- 热门榜
- 高性价比榜
- 收藏榜
- 新品推荐榜
- 反馈较多榜

"避雷榜"这个概念可以保留在内部讨论里，但正式项目里建议叫：

- 反馈较多榜
- 待改进榜
- 低分反馈榜

这样表达更温和，也更适合真实平台。

## 四、角色二：卖家 / 食堂商家

卖家是这个版本里很重要的角色。它让平台不只是学生评价菜品，而是形成了"商家主动运营 + 根据反馈改进"的闭环。

卖家的核心目标是：

- 展示菜品
- 主动推荐菜品
- 查看学生反馈
- 根据留言优化菜品
- 提升菜品曝光和口碑

卖家端也放在微信小程序里，比较符合实际使用场景。商家可以在手机上快速发布推荐、查看留言和处理反馈。

### 4.1 卖家登录与身份认证

卖家也可以使用微信登录，但需要平台管理员审核身份。

建议流程：

```
卖家微信登录 → 提交入驻申请 → 填写商家 / 窗口信息 → 平台管理员审核 → 审核通过后获得卖家权限
```

卖家资料包括：

- 商家名称
- 所属食堂
- 窗口位置
- 营业时间
- 联系电话（可选）
- 经营类型
- 商家简介

### 4.2 菜品管理

卖家可以管理自己的菜品。

功能包括：

- 新增菜品
- 修改菜品信息
- 上传菜品图片
- 设置价格
- 设置口味标签
- 设置菜品状态
- 下架菜品
- 查看菜品评分
- 查看菜品评论

菜品状态可以包括：

- 上架中
- 已售罄
- 暂停售卖
- 已下架

这个功能很实用，因为食堂菜品可能每天变化。

### 4.3 主动推荐菜品

卖家可以主动推荐今日菜品，比如：

- 今日主推
- 新品推荐
- 限时推荐
- 高性价比推荐
- 窗口招牌菜

推荐内容可以包括：

- 推荐菜品
- 推荐标题
- 推荐理由
- 推荐时间
- 展示图片
- 是否置顶

例如：

> **今日主推：黑椒鸡排饭**
> 推荐理由：今日现炸鸡排，分量足，适合午餐。

学生端首页可以展示：

- 商家今日推荐
- 附近食堂推荐
- 本周新品
- 窗口招牌

这能让卖家角色有存在感，不只是被动被评价。

### 4.4 查看留言与反馈

卖家可以查看学生对自己菜品的评价和留言。

功能包括：

- 查看菜品评论
- 查看学生反馈
- 按菜品筛选留言
- 按评分筛选留言
- 查看低分反馈
- 回复学生留言
- 标记反馈处理状态

反馈状态可以设计为：

- 待查看
- 已查看
- 已采纳
- 已改进
- 暂不处理

例如学生留言：

> "这个菜味道不错，但是米饭有点少。"

卖家可以回复：

> "感谢反馈，后续会适当增加米饭分量。"

这就能体现平台的互动价值。

### 4.5 改进记录

这个功能很适合做项目亮点。

卖家可以根据学生反馈发布"改进记录"。

例如：

| 菜品   | 学生反馈 | 改进措施    | 改进时间       |
| ---- | ---- | ------- | ---------- |
| 麻辣香锅 | 口味偏咸 | 已调整底料比例 | 2026-04-24 |

学生端可以看到：

> 商家已根据反馈优化该菜品

这样平台就不只是评价，而是有"反馈—改进—再评价"的闭环。

如果时间有限，可以把它简化成：

- 卖家回复反馈
- 反馈状态改为"已改进"

### 4.6 卖家数据看板

卖家可以查看自己窗口的数据。

功能包括：

- 菜品浏览量
- 菜品收藏数
- 菜品评分
- 评论数量
- 今日推荐点击量
- 最受欢迎菜品
- 反馈较多菜品

如果时间不够，至少保留：

- 菜品评分
- 评论数量
- 收藏数量

## 五、角色三：平台管理员

平台管理员使用 Web 后台，主要负责平台治理和基础数据维护。

管理员核心目标是：

- 管理平台用户
- 审核卖家身份
- 维护食堂基础信息
- 审核内容
- 处理违规信息
- 查看平台数据

### 5.1 用户管理

管理员可以管理学生和卖家账号。

功能包括：

- 查看用户列表
- 查看用户详情
- 禁用违规用户
- 恢复用户账号
- 查看用户评论记录

### 5.2 卖家管理

卖家入驻需要管理员审核。

功能包括：

- 查看卖家入驻申请
- 审核通过 / 驳回
- 修改卖家信息
- 禁用卖家账号
- 查看卖家菜品
- 查看卖家推荐记录

这个模块很重要，因为卖家端如果不审核，平台数据会混乱。

### 5.3 食堂与窗口管理

管理员维护平台基础结构。

功能包括：

- 新增食堂
- 修改食堂信息
- 删除食堂
- 新增窗口
- 修改窗口信息
- 分配窗口给卖家
- 设置食堂营业状态

关系可以是：

- 一个食堂有多个窗口
- 一个窗口对应一个或多个卖家
- 一个卖家管理自己的菜品

为了项目别太复杂，建议你们先设计成：

- 一个卖家对应一个窗口
- 一个窗口下有多个菜品

这样比较清晰。

### 5.4 菜品审核

为了避免卖家乱传数据，管理员可以审核菜品。

功能包括：

- 审核新增菜品
- 审核菜品图片
- 审核菜品修改
- 强制下架违规菜品
- 查看菜品状态

如果觉得审核流程太复杂，可以简化成：

- 卖家发布菜品后默认上架
- 管理员可以后续下架

这对期末项目更友好。

### 5.5 评论与留言审核

因为学生可以评论、留言、上传图片，所以管理员需要内容管理。

功能包括：

- 查看评论列表
- 删除违规评论
- 隐藏不当评论
- 处理举报内容
- 查看图片评价
- 管理敏感词

真实上线时这个模块很重要。期末项目里可以做基础版：

- 管理员查看评论
- 管理员删除评论
- 管理员处理举报

### 5.6 数据统计

管理员可以查看平台整体数据。

建议包括：

- 学生用户总数
- 卖家数量
- 菜品总数
- 评论总数
- 今日抽奖次数
- 热门菜品排行
- 热门商家排行
- 各食堂评分统计
- 用户活跃趋势

这个模块适合做 Web 后台首页，也是答辩展示的加分项。

## 六、整体业务闭环

这个项目最重要的是讲清楚闭环。

可以总结成：

```
卖家发布菜品
       ↓
学生浏览菜品
       ↓
学生通过抽奖或排行榜选择菜品
       ↓
学生就餐后评价 / 留言
       ↓
卖家查看反馈并改进
       ↓
平台管理员审核和管理内容
       ↓
平台根据评分、收藏、反馈继续优化推荐
```

这就是一个完整的平台逻辑。

你们答辩时可以重点讲：

> 本项目不是单纯的菜品展示系统，而是围绕校园就餐场景，构建了学生、商家和平台管理员三方参与的评价与推荐闭环。

## 九、项目核心卖点

### 1. 真实校园需求

解决学生"不知道吃什么"和"容易踩雷"的日常问题。

### 2. 抽奖式推荐

用盲盒、抽奖的方式降低选择困难，让推荐功能更有趣。

### 3. 三方参与闭环

学生评价，卖家改进，平台监管，形成完整业务流程。

### 4. 移动端 + Web 后台结合

学生和卖家使用微信小程序，平台管理员使用 Web 后台，符合不同角色的使用场景。

## 十、最终项目定位

"饭点盲盒"是一款基于微信小程序的校园食堂菜品评价与推荐平台。系统面向学生、卖家和平台管理员三类用户，学生可以通过小程序浏览菜品、参与抽奖推荐、收藏菜品并发表评价；卖家可以通过小程序管理菜品、发布今日推荐、查看学生留言并根据反馈改进菜品；平台管理员通过 Web 后台完成用户管理、卖家审核、菜品管理、评论管理和数据统计。平台以"今天吃什么"为核心场景，通过趣味化抽奖推荐和评价反馈机制，帮助学生提升就餐体验，也帮助食堂商家优化服务质量。
