# "吃点啥" 校园餐饮平台 — 数据库设计文档

## 一、数据库概述

### 1.1 设计目标

本数据库为"吃点啥"校园餐饮与商户评价推荐平台提供数据存储支撑，覆盖用户认证、校园商户管理、菜品管理、学生互动、抽奖推荐、商家反馈、小法庭纠纷等核心业务场景。

### 1.2 技术选型

| 项目 | 说明 |
|------|------|
| 数据库引擎 | MySQL 8.0+ |
| 字符集 | utf8mb4 / utf8mb4_unicode_ci |
| 存储引擎 | InnoDB（支持事务与外键约束） |
| 主键策略 | BIGINT UNSIGNED 自增主键 |

### 1.3 设计规范

- 所有表名、字段名采用 **snake_case** 命名
- 每张表包含 `created_at`、`updated_at` 审计字段
- 状态字段使用 VARCHAR 枚举值，便于扩展
- 关键查询字段建立索引，外键建立约束保证数据完整性

## 六、索引策略

### 6.1 索引设计原则

- **高频查询字段**建立索引（如 status、type）
- **外键字段**自动建立索引
- **联合索引**遵循最左前缀原则
- **唯一索引**保证业务唯一性约束

### 6.2 关键索引示例

| 表名 | 索引名 | 索引字段 | 用途 |
|------|--------|----------|------|

## 七、数据完整性保障

### 7.1 外键约束

所有关联表均建立外键约束，保证引用完整性。删除父记录时需先处理子记录。

### 7.2 唯一约束

| 约束 | 说明 |
|------|------|
| sys_user.username | 用户名全局唯一 |
| sys_user.wechat_openid | 微信 OpenID 全局唯一 |
| sys_user.phone | 手机号全局唯一 |
| (user_id, role_id) | 用户角色不重复 |
| (user_id, dish_id) | 用户对菜品评价/想吃不重复 |
| (user_id, target_type, target_id) | 收藏不重复 |
| (post_id, user_id) | 帖子点赞不重复 |
| (case_id, voter_id) | 庭审投票不重复 |

### 7.3 枚举值校验

状态字段在应用层进行枚举值校验，数据库层通过 VARCHAR 类型存储，兼顾灵活性和可扩展性。
